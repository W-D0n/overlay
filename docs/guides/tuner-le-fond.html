Fond seul dans OBS et page de tuning

Ce guide couvre le mode background-only : une URL OBS qui ne rend que l'animation de fond, réglée en direct depuis la page de tuning. Le moteur de scènes complet (index.html) n'est pas concerné ici.

Vue d'ensemble

Quatre pièces communiquent :

  • background.html — la page à mettre dans OBS. Elle ne fait qu'une chose : afficher l'effet de fond courant.
  • dev/studio.html — l'entrée de création commune aux fonds et aux scènes.
  • dev/background-tuner.html — la page de tuning. Aperçu plein écran + barre latérale rétractable avec la liste des effets, leurs paramètres et les presets.
  • Le serveur d'état (port 4462, lancé automatiquement) — retient le dernier réglage dans dev/data/background-state.json et pousse chaque changement en direct vers OBS.

Concrètement : tu bouges un curseur dans le tuner → l'aperçu change immédiatement → OBS suit dans la seconde → et au prochain démarrage, OBS recharge le dernier état sauvegardé tout seul.

Mettre le fond dans OBS

  1. Lancer start-stream.bat (ou start-dev.bat pour bricoler).
  2. Dans OBS : Source → Navigateur (Browser Source).
  3. URL : http://localhost:5500/background.html
  4. Largeur 1920, hauteur 1080.

Laisser le champ CSS personnalisé vide. OBS injecte ce CSS après celui de la page : une règle ajoutée ici peut forcer un fond, masquer un élément ou changer une taille, mais crée alors une différence entre le tuner et OBS. Pour superposer l'animation sur une capture, utiliser http://localhost:5500/background.html?transparent=1 plutôt qu'une surcharge CSS.

Si le serveur n'est pas encore lancé quand OBS charge la page, ce n'est pas grave : la page attend et se reconnecte toute seule (1 s → 30 s max entre les tentatives).

La page de tuning

Ouvrir http://localhost:5500/dev/studio.html (s'ouvre automatiquement avec start-dev.bat), puis choisir Fonds & presets. L'URL directe dev/background-tuner.html reste disponible pour le diagnostic.

  • La barre latérale se rétracte avec le bouton ◀ / ▶ sur son bord — pratique pour juger le rendu plein écran.
  • Points de départ : Essayer charge une ambiance sans la sauvegarder ; Ajouter à mes presets en crée une copie personnelle.
  • Recherche : le champ filtre les points de départ et les presets personnels par nom, effet ou tag, sans dépendre des accents ni des majuscules.
  • Réglages de l’effet : le menu liste toutes les animations disponibles (+ « (aucun) »). Chaque nombre dispose d’un curseur borné, d’une valeur précise et de son unité.
  • Mes presets : Créer enregistre le réglage courant. URL copie l'adresse stable ; ✎ renomme sans la casser ; ⧉ duplique ; ✕ supprime avec confirmation. Le champ inférieur accepte des tags séparés par des virgules. Nouveau quitte le mode de mise à jour du preset chargé.
  • Sauvegarde portable : Exporter télécharge la bibliothèque personnelle dans un JSON versionné. Importer valide tout le fichier avant écriture, conserve les identifiants connus et suffixe les conflits de nom sans écraser un autre preset. Le tuner affiche d'abord le résumé des créations, mises à jour, noms ajustés et presets ignorés, puis détaille chaque preset : opération, effet, tags et réglages ajoutés, retirés ou modifiés. Un conflit indique le nom demandé, le preset qui le porte déjà et le nom finalement attribué. La liste défile indépendamment afin que Confirmer l'import et Annuler restent accessibles sur un gros fichier. Rien n'est écrit avant confirmation. Si un autre onglet change la bibliothèque entre-temps, tout le détail est recalculé et doit être confirmé à nouveau.
  • Qualité de rendu : Auto plafonne le DPR à 2 ; Performance OBS le limite à 1. La ligne voisine affiche FPS et DPR.

La ligne de statut en bas de la barre indique si le serveur d'état répond. Si elle est rouge, lancer start-dev.bat ou start-stream.bat.

Un fond par scène OBS

Deux façons, non exclusives :

  1. Une source Navigateur par preset — le bouton URL d'un preset donne une adresse stable (background.html?preset=<id>) à coller dans la scène OBS voulue. Simple, sans configuration.
  2. L'association automatique (section « Scènes OBS » du tuner) — changer de scène dans OBS change le fond de la source qui suit l'état courant.

Pour la seconde : activer le serveur WebSocket dans OBS (Outils → Paramètres du serveur WebSocket), créer un fichier .env à la racine avec OBS_WS_URL et OBS_WS_PASSWORD (gabarit dans .env.example), puis relancer start-dev.bat. Dans la section Scènes OBS, chaque scène détectée reçoit un preset.

Une scène sans association ne change rien — un oubli ne noircit jamais un live. L'association reprend la main sur un réglage fait à la main au prochain changement de scène, et une URL ?preset= n'est jamais concernée. L'association se fait par nom : renommer une scène dans OBS casse le lien.

Repérer un preset d'un coup d'œil

Chaque ligne porte une vignette de son effet. Survole-la pour voir l'animation : au repos c'est une simple image, donc une longue liste ne coûte rien à la machine. Sur les effets très clairsemés (WaterRipple, StarsParallax), l'image figée montre peu de choses — c'est le survol qui les identifie.

Ton identité à l'écran — le branding

La section Branding porte ton pseudo et tes réseaux. Le contenu est commun à tous les presets : c'est ton identité, elle ne change pas d'une scène à l'autre.

  • Placer le bloc : attrape-le dans l'aperçu. Sa position est enregistrée en pourcentage du canvas. Posé dans la moitié droite il s'aligne à droite, en bas il remonte.
  • Masquer sur un preset : la case « Afficher sur ce preset ». Le branding disparaît dans OBS mais reste visible estompé dans l'aperçu, sinon tu ne pourrais plus le repositionner.
  • Les tailles sont en pixels pour un canvas 2560×1440, et le bloc est mis à l'échelle automatiquement si le canvas change.

Comment un preset arrive — les transitions

La section Arrivée de ce preset décrit la façon dont ce preset remplace le fond précédent : type (fondu ou balayage), durée (0 à 2000 ms), courbe, et sens pour le balayage.

La transition se joue quand le preset arrive : clic sur un preset, ou changement de scène OBS associé. Bouger un curseur ne la rejoue pas. L'ouverture de la Browser Source n'anime jamais. Pendant la transition, deux effets tournent en même temps — borné à 2 secondes, mais c'est le moment le plus coûteux pour la machine.

Vérifier avant un live

Le bloc Prêt pour le live se contrôle automatiquement à l'ouverture du tuner. Le bouton Revérifier permet de relancer le diagnostic après avoir changé un effet, un preset ou le profil de rendu. Les résultats et leurs coches se rejouent alors dans l'ordre ; le mouvement est désactivé si le système demande moins d'animations.

Le diagnostic est entièrement en lecture seule : il ne modifie ni le fond courant, ni les presets, ni la configuration OBS. Il vérifie :

  • la disponibilité du serveur d'état ;
  • la validité de l'effet ou du preset sélectionné ;
  • l'adresse à utiliser dans la Source Navigateur OBS ;
  • la présence d'une mesure locale FPS/DPR ;
  • le relais optionnel, qui n'est pas requis pour une URL de fond autonome.

Le résultat est Prêt, Attention ou Bloquant. Chaque ligne concernée propose une action directe : copier l'URL, choisir un effet ou un preset, ou réessayer après avoir relancé start-dev.bat ou start-stream.bat.

À confirmer dans OBS. La mesure FPS vient du navigateur courant : elle confirme que l'animation tourne, mais ne certifie pas ses performances dans OBS. Faire une dernière vérification visuelle avant le live.

Couleurs, palettes et scènes

  • tokens.css contient les couleurs de l'identité Atelier utilisées par l'interface.
  • Les couleurs des effets acceptent une valeur CSS libre : hex, rgb(...), oklch(...) ou var(--nom-du-token).
  • components/color-palette.json contient les couleurs nommées et les gradients de travail destinés au tuner.

Deux modes sont disponibles :

  • background.html suit l'état courant du tuner ; toutes les sources utilisant cette URL affichent le même effet.
  • background.html?preset=identifiant-stable&transparent=1 reste attachée à ce preset, même après renommage. Les anciennes URL par nom restent compatibles.

Pour avoir un fond différent par scène, créer les presets, utiliser leur bouton URL, puis ajouter une source Navigateur par URL dans OBS. Activer Arrêter la source lorsqu'elle n'est pas visible pour ne laisser tourner que la scène affichée.

Ajouter une nouvelle animation — sans agent

Le tuner et l'URL OBS n'ont jamais besoin d'être modifiés : ils lisent tout depuis trois déclarations. Ajouter une animation = créer un fichier et ajouter trois lignes.

1. Le composant — components/MonEffetBackground.js

Une fonction qui retourne { el, update, destroy }. Squelette minimal fonctionnel :

// @ts-check
/**
 * MonEffetBackground.js — description de l'effet.
 * @param {{ speed?: number, color?: string }} [options]
 * @returns {import('../types.js').ComponentInstance}
 */
export function MonEffetBackground(options = {}) {
  let speed = options.speed ?? 1;

  const canvas = document.createElement('canvas');
  canvas.style.cssText = 'position:absolute;inset:0;width:100%;height:100%;pointer-events:none;';
  const ctx = canvas.getContext('2d');

  let rafId = 0;
  function tick() {
    rafId = requestAnimationFrame(tick);
    // ... dessiner une frame ici ...
  }
  rafId = requestAnimationFrame(tick);

  return {
    el: canvas,
    update(newOptions) {
      // appliquer les nouvelles options sans recréer le canvas
      if (typeof newOptions?.speed === 'number') speed = newOptions.speed;
    },
    destroy() {
      cancelAnimationFrame(rafId); // OBLIGATOIRE — sinon l'animation continue en fantôme
    },
  };
}

Le plus simple est de partir d'une copie d'un effet existant proche (components/RainBackground.js est un bon modèle : canvas, resize, couleurs via tokens). Détail complet du contrat dans Créer un composant.

2. Le registre — deux fichiers, une ligne chacun

// component-names.js — ajouter le nom dans la liste :
'MonEffetBackground',

// component-registry.js — importer + ajouter au registry :
import { MonEffetBackground } from './components/MonEffetBackground.js';
...
MonEffetBackground,

3. Le schéma de champs — dev/component-field-schemas.js

Une entrée dans BACKGROUND_FIELD_SCHEMAS décrivant les paramètres réglables. C'est elle qui génère le formulaire du tuner :

MonEffetBackground: [
  { key: 'speed', label: 'Vitesse', type: 'number', min: 0, max: 5, step: 0.05,
    unit: '×', control: 'slider', default: 1 },
  { key: 'color', label: 'Couleur', type: 'color', default: '#C8B97A' },
],

Types disponibles : 'text', 'number', 'select' (+ choices), 'textarea', 'color' (picker + palette + CSS libre) et 'colors' (liste ajout/retrait + gradients).

Tout champ numérique doit déclarer min, max, step et control: 'slider'. Les profils communs vivent dans NUMBER_FIELD_GUIDANCE.

4. Vérifier

bun test

Les tests de cohérence existants attrapent les oublis : un nom déclaré sans factory, une factory sans schéma, etc. Ensuite, recharger le tuner — le nouvel effet est dans le menu déroulant, avec son formulaire, ses presets, et l'URL OBS le prend en charge sans rien toucher.

Faire évoluer le tuner

dev/background-tuner.html ne contient plus sa logique métier. Selon le changement :

  • Champ : déclaration dans dev/component-field-schemas.js, rendu commun dans dev/background-field-renderer.js.
  • Requête d'état : méthode et route uniquement dans dev/background-state-client.js.
  • Action de preset : dev/background-preset-controller.js.
  • Import/export : dev/background-preset-transfer-controller.js, en conservant la prévisualisation puis la confirmation avant écriture.
  • Montage, qualité ou FPS : dev/background-preview-controller.js ; l'état courant et le preset actif vivent dans dev/background-preview-session.js.
  • Contrôle pré-live : synthèse dans dev/background-live-readiness.js, rendu dans dev/background-readiness-controller.js.
  • Câblage au démarrage : dev/background-tuner-runtime.js.

Les identifiants HTML, URL et routes serveur font partie du contrat : ne pas les recopier dans plusieurs modules. Ajouter un test à l'interface concernée, lancer bun test, puis vérifier les parcours du Studio à 1920×1080.

Performance et cycle de vie

Les canvas utilisent components/canvas-runtime.js : DPR 2 maximum en Auto, DPR 1 avec ?quality=performance. Le tuner et background.html démontent l'effet quand leur page devient invisible, puis remontent le dernier état à la reprise. Dans OBS, conserver également Arrêter la source lorsqu'elle n'est pas visible.

Récap : 1 fichier créé (le composant) + 3 lignes (nom, registry, schéma). Rien d'autre à modifier — ni background.html, ni le tuner, ni le serveur.
