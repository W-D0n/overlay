# Sécurité — Overlay Stream

Modèle de menace de l'outil local (serveur statique + serveur d'état + client OBS WebSocket
lecture seule). Le relais et son authentification par jeton sont archivés avec le moteur de scènes.

## Surfaces

| Surface | Mesure |
|---|---|
| Écoute réseau | `127.0.0.1` uniquement (`LOOPBACK_HOST`, `server/local-access-policy.js`). Les ports 5931 et 5932 sont injoignables depuis le réseau local. |
| Fichiers servis | Liste blanche : `src/`, `studio/` et fichiers racine `html/js/css/json/png/svg/ico/woff2`. Dotfiles, `docs/`, `src-tauri/`, état persisté : 404. |
| Pages web tierces | Toute requête (HTTP ou WebSocket) dont l'`Origin` n'est pas locale reçoit 403 ; un `Host` non local aussi (anti DNS rebinding). Deux exceptions, étroites : le canal Twitchat, protégé par un jeton (ligne suivante), et la **lecture seule d'un fichier de la médiathèque** (`GET /assets/<32 hexadécimaux>`) par une page isolée, dont l'`Origin` est `null` (couche Code, ligne dédiée). L'`Origin` `null` n'ouvre ni l'état, ni la liste de la médiathèque, ni une écriture, ni une suppression (essai sur un vrai serveur : `server/background-state-server.test.js`). Contrepartie assumée : une page `sandbox` ou `data:` d'un site tiers, qui a aussi l'`Origin` `null`, pourrait lire un fichier de la médiathèque dont elle connaîtrait l'identifiant (128 bits, non devinable, jamais affiché hors du Studio). |
| API d'état | Pas d'authentification : l'accès est réservé à la machine. Les entrées sont validées (`background-state-format.js`) avant écriture. |
| Images importées | `POST /assets` : le type est reconnu à l'en-tête du fichier (PNG, JPEG, GIF, WebP), jamais au nom ni au `Content-Type` du client ; **SVG refusé** (scripts et références externes) ; 15 Mo et 25 millions de pixels au plus, dimensions lues sans décoder ; identifiant = empreinte du contenu (aucun chemin n'est jamais construit depuis une entrée) ; servies avec `X-Content-Type-Options: nosniff`. Un lot importé (version 4) est contrôlé de même (type lu dans les octets décodés, 64 images et 128 Mo au plus) et une image dont l'empreinte ne correspond pas à son identifiant fait refuser le lot. Elles vivent à côté du fichier d'état, dans `data/`, que le serveur statique ne sert pas. |
| Twitch (EventSub, autorisation par code d'appareil) | Client **Public** de Twitch : aucun secret d'application. Seuls sortent vers Twitch l'identifiant client, les jetons et le jeton de session ; les jetons vivent dans `<état>.connections.json` (mêmes protections que le mot de passe OBS), ne sont **jamais** renvoyés par l'API, et le jeton de rafraîchissement (usage unique) est écrit avant d'être utilisé. Portées minimales vérifiées après autorisation (`moderator:read:followers`, `channel:read:subscriptions`, `bits:read`). Une alerte de Twitch passe par la même validation et le même limiteur que toute alerte. Déconnecter révoque le jeton chez Twitch. Les adresses de Twitch ne se redirigent que par variables d'environnement du processus (essais). |
| Canal Twitchat (`/twitchat-ws` et `/`, WebSocket) | **Seule surface qui accepte une Origin hors boucle locale** : la page de Twitchat est hébergée ailleurs. Le filtre est un **jeton** de 24 octets (48 hexadécimaux) tiré du générateur du système, dans l'adresse ou dans chaque message, comparé sans court-circuit ; le Host reste exigé local (DNS rebinding refusé). Un message est borné (4 Ko, 64 Ko pour la connexion), validé comme toute alerte (`server/integrations/alert-event.js`), et un limiteur retient les rafales (20 alertes / 5 s). Le jeton se régénère depuis le Studio (les connexions sont coupées). Il n'est ni journalisé ni envoyé à la page de rendu. |
| Couche Code (HTML, CSS, JavaScript écrits ou importés) | **Le code ne s'exécute jamais dans le Studio ni dans la page de rendu** : une `iframe` `sandbox="allow-scripts"` (aucun `allow-same-origin`, `allow-popups`, `allow-forms`, `allow-top-navigation`…), `allow=""` (aucune permission du navigateur déléguée, donc ni micro ni caméra : le son lui est transmis par message), `referrerpolicy="no-referrer"`, chargée par `srcdoc`. Origine opaque : ni cookies, ni stockage, ni accès à la page qui l'héberge, à l'API du Studio ou à ses jetons. Le document porte, avant tout code de l'auteur, une **politique de sécurité du contenu** : `default-src 'none'`, scripts, styles, images, polices, médias et connexions limités à `<serveur d'état>/assets/` (la médiathèque seule, jamais le reste du serveur), `base-uri 'none'`, `form-action 'none'`, aucun sous-document réseau : pas d'Internet, pas de WebSocket, pas de `fetch` vers l'état. Une bibliothèque (three.js) est donc un fichier de la médiathèque, jamais une adresse extérieure : le live ne dépend d'aucun réseau. Messages hôte ↔ page sur un protocole versionné ; l'hôte ne lit que ceux de **cette** `iframe`, la page ne lit que ceux de son parent. Une page qui se **redirige d'elle-même** (aucune directive ne l'interdit) est détectée au chargement qu'elle provoque, vidée aussitôt et l'auteur prévenu ; **limite restante** : la requête de cette navigation part déjà, donc l'adresse IP de la machine est visible du site visé — comme pour toute source navigateur d'OBS, qui n'a aucune de ces protections. Une scène **importée** qui contient du code exige une case cochée (« j'ai compris ») avant l'import. |
| Couche Shader (GLSL) | Un shader n'a **ni réseau, ni stockage, ni accès à la page** : il est compilé par le pilote graphique et ne peut que calculer des couleurs. Il tourne donc dans la page de rendu, sans bac à sable (`couche-shader.md` S2). Le danger est son **coût** : une boucle sans fin fait réinitialiser le pilote graphique (l'affichage de tout l'ordinateur se fige quelques secondes). Rien n'est exfiltrable ; l'import d'un lot qui en contient exige la même case cochée que le code, avec un texte qui parle de la carte graphique. La qualité de rendu (plein, moitié, quart) est le seul levier de coût ; un contexte perdu est dit et le shader est recompilé à la restauration. |
| Fichiers de la médiathèque pour le code (scripts `.js`/`.mjs`, modèles `.glb`) | Un modèle est reconnu à son en-tête (`glTF`), jamais au nom. Un script n'a pas d'en-tête : il est reconnu à son extension **et** à son contenu (UTF-8 valide, aucun octet nul, 5 Mo au plus) ; une image, une police ou un modèle l'emportent toujours sur le nom. Servis avec leur type (`text/javascript` : un module l'exige), `nosniff`, un identifiant tiré du contenu. Un script ne s'exécute que dans la page isolée d'une couche Code. Une référence `asset:<id>` écrite dans le code compte comme un usage : le fichier ne se supprime plus, et il voyage dans un export. |
| OBS WebSocket | Client en lecture seule (scène active, liste des scènes). Le mot de passe se saisit dans le Studio (Réglages) et vit dans `<état>.connections.json` (dossier `data`, ignoré par git, jamais servi, mode `0o600` là où le système le permet) ; `.env` reste lu en repli. L'API ne le renvoie jamais (`GET /connections` dit seulement « enregistré »), l'écriture exige l'en-tête `X-Overlay-Control`, ni le journal ni l'export des scènes ne le contiennent. |

Tests : `server/local-access-policy.test.js`, `server/background-state-server.test.js` (Origin étrangère refusée, Origin `null` limitée à la lecture d'un fichier), `src/shared/asset-format.test.js`, `src/shared/bundle-assets.test.js`, `server/routes/asset-routes.test.js` (faux fichier, fichier trop lourd, identifiant en forme de chemin, origine étrangère, script et modèle), `src/components/code-document.test.js` (politique, passerelle), `src/components/CodeLayer.test.js` (isolation, messages, navigation) et l'essai de bout en bout `e2e/suites/33-couche-code.e2e.js`, où le code tente de sortir **de l'intérieur** (réseau, stockage, page parente, fenêtre, sous-document) et rapporte ce qui lui est arrivé, avec la directive de la politique qui l'a bloqué.

## Règles d'exploitation

1. Ne pas rediriger ces ports vers le réseau (proxy, tunnel, partage de port d'une VM) : l'API d'état n'a pas d'authentification.
2. Un mot de passe OBS ou un jeton vu par un tiers est à régénérer, même s'il n'a transité qu'en local.
3. Les événements entrants (alertes, chat) sont validés côté source avant d'atteindre `POST /event` ; jamais de texte utilisateur brut.
4. Avant l'ajout d'une source réseau (EventSub, relais cloud), ce document est à reprendre : chaque nouvelle surface a besoin d'une authentification.
5. N'importer une scène que si on en connaît l'auteur : elle peut contenir une couche Code ou Shader. Le bac à sable protège le Studio, ses fichiers et ses jetons ; il n'empêche pas une scène d'afficher ce qu'elle veut à l'antenne.
6. Le code d'une couche est lu avant d'être publié, comme n'importe quel code que l'on exécute : une page isolée ne voit rien du Studio, mais elle dessine dans votre live.
